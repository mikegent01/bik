## Intake: Players.json → originals → import-ready

The party's live export is `Players.json` in the repo root: a single file
holding all twelve actors. Foundry imports one actor per file, so the intake
pipeline splits it and feeds the existing rebuild:

```bash
python3 tools/fix-players-intake.py    # one-time fixes (idempotent): Dan's
                                       # background pointer, Wario NPC→PC
python3 tools/add-bowser-to-players.py # takes bowser.json into the roster
                                       # (idempotent; see "Bowser as a
                                       # player character" below)
python3 tools/split-players.py         # Players.json → original-fvtt-*.json
python3 tools/rebuild-actors.py        # originals → import-ready + NO-SPECIES
python3 tools/rebuild-actors.py --check   # verify, write nothing
```

Per-actor decisions (Dan and Eager keeping the second species) live in
`OVERRIDES` in `rebuild-actors.py`, so nothing here is a hand-edited
artefact. The `--check` mode runs in `check-all.py` as **actor exports**,
and `tools/tests/test-players-split.py` guards the split itself (every
entry accounted for, originals JSON-equal to the live entries).

**Supersede policy:** the Players.json versions replace the older
single-actor originals for Dan, Hjumpik, Toad Lee and Waluigi (the old
files are retired; git history keeps them). Aurelian and Azure have no
live export, so their files stand. Wario's motorbike is **not** split —
it stays generated by `tools/build-wario-motorbike.py`, and the split
test fails on drift between the live entry and the generated file.

**Bridge:** `python3 tools/split-players.py --watch` polls Players.json
and re-splits + rebuilds whenever it changes, so the import-ready files
stay fresh while the export is being edited. Nothing can push data into a
live Foundry world from outside, but the import side is no longer one file
at a time — see **Mass import / export** below: one click in Foundry
imports a whole packet (folders included) from a file, a GitHub raw URL or
the Data folder.

Regenerate any single file:

```bash
cd Reputation-Matrix2/actors
python3 ../../tools/sanitize-foundry-actor.py original-fvtt-Actor-NAME.json \
  --write fvtt-Actor-NAME.json
```

## Mass import / export — the session loop

The Foundry module [`../Foundry/mass_import/`](../Foundry/mass_import/README.md)
(`waluipedia-mass-import`, install via the manifest URL
`https://mikegent01.github.io/bik/Reputation-Matrix2/Foundry/mass_import/module.json`)
adds **Export all** / **Import** buttons to the Actors sidebar. Export writes
`<world>-all-actors.json` with every actor **and its folder path**
(`flags["waluipedia-mass-import"].folderPath`); Import takes that file — or
the old macro export, a bare array like `Players.json`, or a single
`fvtt-Actor-*.json` — recreates the folders, creates missing actors with
their `_id` kept, updates existing ones in place, syncs items/effects, and
checks every image path against the server. The old
`game.actors.contents.map(a => a.toObject())` macro export still imports (it
just has no folders; everything lands in the root or under "Root folder").

[`tools/foundry-bridge.py`](../../tools/foundry-bridge.py) is the repo side
(stdlib only, tested by `tools/tests/test-foundry-bridge.py`):

```bash
# 1. split the end-of-session export into one file per actor, directories = folders
python3 tools/foundry-bridge.py split ~/Downloads/<world>-all-actors.json \
    --out Reputation-Matrix2/actors/worlds/<world> --prune
# 2. connect images: characters.json portraits, portraits/<slug>.*, the image library
python3 tools/foundry-bridge.py link-images Reputation-Matrix2/actors/worlds/<world> --write
# 3. implement changes/states/items from a small changes.json (or edit the JSON by hand)
python3 tools/foundry-bridge.py apply changes.json Reputation-Matrix2/actors/worlds/<world> --write
python3 tools/foundry-bridge.py check Reputation-Matrix2/actors/worlds/<world>
# 4. combine into one import packet and copy the PNGs it references into Foundry Data
python3 tools/foundry-bridge.py combine Reputation-Matrix2/actors/worlds/<world> \
    --out Reputation-Matrix2/actors/worlds/<world>/import.json --world <world>
python3 tools/foundry-bridge.py install-images Reputation-Matrix2/actors/worlds/<world> \
    --foundry-data "/path/to/FoundryVTT/Data"
```

Then **Import** the `import.json` in Foundry (upload it, paste its GitHub raw
URL once the branch is pushed, or point at a copy inside Data). Moving an
actor between folders is editing `folderPath` (or moving the file: `combine`
derives the path from the directory when the flag is absent). A
`changes.json` is a list of `{match, set, unset, rename, folderPath,
addItems, removeItems, addEffects, removeEffects, delete}` entries — see the
docstring at the top of the bridge. The 955 packet below ships its
`import.json` pre-built (`check-all` keeps it current), and the live
`midlands` world is already split under
[`worlds/midlands/`](worlds/README.md) from `midlands-all-actors.json`.

### The suite: `tools/sheets-suite.py` (what `start.py` runs)

Steps 1–4 above, plus the sheet rules, as one process that `start.py` starts
with the site (tick **Character sheets**; `--no-sheets` to skip):

```bash
python3 tools/sheets-suite.py            # one pass
python3 tools/sheets-suite.py --watch    # re-run when an export / Players.json / a changes file changes (start.py does this)
python3 tools/sheets-suite.py --check    # read-only; what tools/check-all.py runs
```

A pass: **intake** (`Players.json` newer than its originals → the intake
chain), **split** (an export newer than the mirror's `manifest.json` — the
repo-root copy or the newest `<world>-all-actors*.json` in Downloads, copied
into the root — → `split --prune`), **promote** (below), **changes** (every
[`changes/*.json`](changes/) whose `appliesTo.exportedAtOrBefore` still
covers the mirror's export → `apply --write`; a later export already carries
the table's version of those items), **check**, **build**
(`build-character-sheets.py`), **combine** (`worlds/<world>/import.json` and
`worlds/<world>/players-import.json` — the Players folder only — both
git-ignored build artefacts), **publish** (below) and **verify**
(`check-sheets.py`, `promote-player-sheets.py --check`). It ends by printing
the URLs: the sheets page and the packet to paste into **Mass import → URL**
(`http://127.0.0.1:8765/Reputation-Matrix2/actors/worlds/midlands/players-import.json`;
`start.py` sends `Access-Control-Allow-Origin: *` so Foundry can fetch it) —
though with the publish step and the module's **Sync** button no URL is
needed any more.

#### Publish: the suite writes into your Foundry Data folder

Everything above only touched the checkout; Foundry never saw a thing until
a URL was pasted — and the wrong URL (`data/sheets.json`, the site's sheet
*index*) gave an uncaught error. Now every pass also **publishes**:

| What | Where in `<FoundryVTT>/Data` | Why |
| --- | --- | --- |
| `players-import.json`, `import.json`, `manifest.json`, `packets.json` (stamps + the other places the same packet lives) | `npc/waluipedia/<world>/` | the module's **Sync** button reads this first — same origin, no URL, no CORS |
| `cast/import.json` (+ `packets.json`) | `npc/waluipedia/cast/` | Sync's `cast` scope offline |
| the Mass Import module, kept identical to `Reputation-Matrix2/Foundry/mass_import/` | `modules/waluipedia-mass-import/` | the published zip on gh-pages lags until the branch merges; this is always the version in the checkout — reload Foundry (F5) when the pass says so, enable it once under *Manage Modules* |
| every image the sheets reference (`portraits/*`, `assets/images/**`, …) that lives in the repo | `portraits/`, `assets/…` (same relative paths) | Foundry serves `img` paths from Data; a path that is not there is a broken token. Copies, not symlinks (symlinks need admin / developer mode on Windows). dnd5e/core icon paths are left alone |

The Data folder is **found automatically**: `--foundry-data DIR` (also
`start.py --foundry-data DIR`, or the entry in the launcher window),
`WALUIPEDIA_FOUNDRY_DATA`, Foundry's own `FOUNDRY_VTT_DATA_PATH` (the folder
above `Data`), the `dataPath` in `Config/options.json`, then the OS default
(`%LOCALAPPDATA%\FoundryVTT\Data` on Windows, `~/.local/share/FoundryVTT/Data`
on Linux, `~/Library/Application Support/FoundryVTT/Data` on macOS). A path
that has no `worlds/ systems/ modules/` inside is reported, never written
to. Not found → the pass says so and Sync in Foundry falls back to the
launcher URL, then GitHub. `--no-publish`, `--no-module-install`,
`--no-images` switch the parts off; `--check` only reports what it would
copy.

Then in Foundry: **Actors sidebar → Sync** (module ≥ 1.3). It finds the
packet (Data → launcher → GitHub), rebuilds the folders from each actor's
`folderPath` (no more "all NPCs at the root" — that happened when actors were
imported without the flag), creates what is missing, updates the rest in
place by id, replaces an NPC statblock with the character sheet under the
same id when the type changed, and shows a summary: replaced / changed / new
/ unchanged, per actor the XP change, class line, items gained or lost,
folder moves, a *Level up at the table* banner when the ledger is ahead of
the sheet, and where it looked. Shift-click for the review table first.

Under `--watch` a pass that blows up is reported like a failed step and the
watcher stays up for the next export. On Windows a piped stdout is cp1252,
which cannot spell `→`: the suite speaks UTF-8 on its own streams, runs
every child tool with `PYTHONIOENCODING=utf-8` / `PYTHONUTF8=1` and decodes
them as UTF-8, and `start.py` reads it the same way — no code page can
kill a pass.

## If the species error persists after importing

Two things cause this, and the first one is not a bug in the file:

**1. You are importing an old copy.** The `tools/item sheet examples/sanitized/`
folder no longer exists — these files moved here. Pull the branch before
importing, and check the file you pick is from `Reputation-Matrix2/actors/`.

**2. A phantom species pointer.** dnd5e stores `system.details.race` next to
the race item. If that pointer names an item id that is not in `items[]`, the
sheet believes a species exists that you cannot see or delete on the sheet,
and `Race._preCreate` refuses the new one. **The original exports carried
dangling or mislabelled pointers of this kind**, so this was almost certainly the real blocker.
The sanitizer now relinks or clears them (`dangling-detail-pointer`,
`detail-pointer-relinked`), and `--clear-species` clears the pointer along with
the item. Dan's background pointer (free text instead of the Dimensional
Escapee item id) is repaired one step earlier, at intake by
`tools/fix-players-intake.py`, so the sanitizer never sees the broken state.

Free-text values such as `race: "Archfey-Touched"` are legal on **NPCs** and
are left alone. On a **character** the same field is a document pointer, so a
label there (Toad Lee carried `race: "Toad"` while owning a real species item)
is the same phantom-species state and gets relinked to the actual item.

If it still fails, delete the species on the sheet by hand, save, and re-run
the Plutonium import.

## "Only a single Species can be added to a Player Character"

**This is not a defect in the file and no amount of sanitizing fixes it.**

Hjumpik already has a species (`Mountain Dwarf`). dnd5e's `Race._preCreate`
refuses to create a second one, Plutonium's task still expects every requested
document back, and the shortfall surfaces as
`Number of returned items did not match number of input items!` — a misleading
message for a plain refusal.

To import a new species onto any character, the existing one has to be gone
**first**. Either delete it on the sheet and re-run the Plutonium import, or
import that character's `-NO-SPECIES.json`, which has the species, its racial
features and the `details.race` pointer already removed:

```bash
python3 ../../tools/sanitize-foundry-actor.py \
  original-fvtt-Actor-hjumpik-deldkur-Qir5aDX8bkL5lt1c.json \
  --clear-species \
  --write fvtt-Actor-hjumpik-deldkur-Qir5aDX8bkL5lt1c-NO-SPECIES.json
```

That file drops `Mountain Dwarf` plus one copy each of the doubled
`Dwarven Resilience` and `Stonecunning` feats (102 → 99 items). It leaves the
surviving `feat`-typed copies and `Darkvision` in place: a plain feat can just
as easily be a class ability, so deleting by name would risk real content. The
PHB'24 Dwarf import will re-add its own copies — delete the leftovers by hand
if they stack.

| Decision | Evidence |
|---|---|

spells — an earlier build tagged them by mistake.) Her fey species (flight 50 ft, hover, darkvision 120 ft,

the sanitizer clean.

### Why Bard, in numbers

`tools/analyze-aurelian-class.py` scores every full-caster list against the
28 spells she already had. It is pure counting — the only judgement is the
hand-entered spell/class table, and spells whose 2014 and 2024 lists differ
are reported separately so an edition disagreement cannot change the answer
silently.

| Class | Coverage (2024 PHB) |
|---|---|
| **Bard** | **25 / 28 — 89%** |
| Wizard | 19 / 28 — 68% |
| Sorcerer | 18 / 28 — 64% |
| Warlock | 12 / 28 — 43% |
| Druid | 12 / 28 — 43% |
| Cleric | 6 / 28 — 21% |

A six-spell gap to the runner-up is not close. Her school profile is
**57% enchantment and illusion** (10 enchantment, 6 illusion), which is the
Bard's core identity, and the three misses are trivially covered by Magical
Secrets.

Warlock deserves a mention because Archfey patron matches her fiction well,
but it covers only 12 of her spells and pact magic gives 2 slots where her
sheet already specifies 4/3/3/3/1. It would mean rewriting her spellcasting
from scratch rather than expressing what is already there.

| `../tools/item sheet examples/fvtt-Actor-bowser,-warlord-of-darkland-7cIOR2o5eLfnODP2.json` | The **boss**. `type: "npc"`, CR 15, 14 items, HP 230 (`20d12 + 100`), natural AC 21, Legendary Actions, Legendary Resistance. Still the antagonist statblock; left untouched. |
| `fvtt-Actor-bowser-kzNSSjAedvhKTfZC.json` | The **player character**. A live export from the campaign world `dnd-part-2`, already `type: "character"`. Level 8 Fighter (Rune Knight), Tortle, Disgraced Noble, 122 items, HP 72, AC 17, XP 34,000. |

**He was taken in, not converted.** No `build-bowser-pc.py` exists and none
should: the live sheet carries the same `exportSource.worldId` as every other
actor in Players.json, so it *is* the sheet being played at the table.
Reasoning a class out of the CR-15 boss block would have invented a character
— a Barbarian, at the wrong level, with the wrong species and three times the
hit points — that nobody has ever played. This is the Waluigi ruling applied
again: **trust the game, not the reconstruction.**

`tools/add-bowser-to-players.py` appends the export to Players.json and does
nothing else. It sets exactly two fields the root-level export omits:

* `_id` — taken from the sheet's own `_stats.exportSource.uuid`
  (`Actor.kzNSSjAedvhKTfZC`), never invented, so the link back to the live
  world survives.
* `sort` — continues the file's existing sequence.

No stat, item or class decision is made anywhere in that script. From there
he goes through the normal pipeline:

```bash
python3 ../../tools/add-bowser-to-players.py            # idempotent
python3 ../../tools/add-bowser-to-players.py --check    # report only
python3 ../../tools/split-players.py
python3 ../../tools/rebuild-actors.py
```

**Sanitizer bug this uncovered — two subclasses were being deleted.** His
Fighter class exports with an empty `system.identifier` (Foundry only fills
that field in for compendium classes). `rule_orphan_subclass` matched
subclasses against class identifiers, found no `"fighter"`, and removed
**both Rune Knight and Champion** — real, played features, silently dropped:
Cloud/Frost/Fire Rune, Giant's Might, and the two Fighting Styles that
Champion grants. The rule now falls back to the slugified class *name*, so
the link resolves. Regression tests cover the blank-identifier case and a
multi-word class name. Anyone importing a live export with a
non-compendium class was hitting this.

**Remaining findings on his sheet** (reported, not silently fixed): his
`details.race` held the label `Tortle` and `details.background` pointed at a
missing id — both relinked to the real items. His portrait
`player/bowser.png` is not in the asset manifest, so it falls back to a
placeholder icon, exactly like Wario's (see *Known remaining 404s*).

## The Oracle and Orange T as NPCs

`tools/build-sanctum-npcs.py` builds both, **one file per character**:
`fvtt-Actor-the-oracle.json` and `fvtt-Actor-orange-t.json`. They are
`type: "npc"`, and the NO-SPECIES variant is generated for characters only,
so neither produces a second or third file.

```bash
python3 ../../tools/build-sanctum-npcs.py            # write both sheets
python3 ../../tools/build-sanctum-npcs.py --check    # verify, write nothing
```

**Three names collide in this archive and they are three different people.**
Anyone filing here should check which one they mean before touching a record:

| id | who | built here |
|---|---|---|
| `the_oracle` | The Oracle, "Orantha Cornelius — suspected". Custodian of Raventree Manor. | yes |
| `orange_t` | Orange T, the orange Toad who treated Bones in the collapsing library. Later becomes the God Toad. | yes |
| `orangus_cornelius` | Orangus Cornelius, the defenestrated vampire lord. | no — separate article |

**Levels come from the XP ledger** (`data/abilityPoints.json`), which is the
authority for level and XP — not from these sheets. The Oracle is level 8
(39,250 XP); Orange T is level 2 (320 XP). CR was set to match.

**The Oracle — CR 8, 127 HP, AC 16.** INT/CHA-forward, because the record is
knowledge, timing and negotiation and never physical force. Features are taken
straight from his article's `notableFeatures`: *Checkpoint Reality* (he
survived Green T's bullet to the brain by checkpointing — "not healing, not
dodging"), *Titan Growth* (granted to Markop at Spider Grove), *Scheduled
Disclosure*, *Custodian of the Vats*, *Ritual Custodian*, *Identity
Unresolved*. **Alignment is deliberately `unaligned`** — the archive holds the
question of his motives open and a sheet should not close it.

**Orange T — CR 2, 22 HP, AC 13.** Deliberately low: the character works
because he is positioned where powerful people do not think to look.
*Already There* (never observed arriving), *Banishment* (he banished both Dans
on a technicality of consent and said "oh oops"), *Field Medicine*, *Sees What
You Cannot*, *Practiced Deflection*.

**The God Toad is not on Orange T's sheet.** His later ascension via a Star
Fragment is a separate entity with its own XP entry (`godtoad`, level 3) and
its own `artifacts.json` record. Granting divine power to the level 2 sheet
would collapse two eras of the character into one file. The feature *A Future
Nobody Has Audited* records the hook without granting the power.

Both sheets pass the sanitizer with **zero findings** — no import-blocking
faults and no image rewrites; every icon path was checked against the asset
manifest before it was used. Both are registered in `ACTOR_SHEETS` in
`index.html`. Orange T has no `characters.json` article yet, so his viewer
entry has no wiki cross-link.

## Wario's motorbike as an NPC

`fvtt-Actor-wario-motorbike.json`, generated by
`tools/build-wario-motorbike.py`. This is the physical motorbike from the
Scorncrow Skirmish record — the one Wario rode into the grove and stalled in
the leaves and branches.

```bash
python3 ../../tools/build-wario-motorbike.py            # write the NPC export
python3 ../../tools/build-wario-motorbike.py --check    # verify, write nothing
```

**Type `npc`, 8 items.** It is a vehicle, not a character, so there is no
species and no `-NO-SPECIES` variant.

| Decision | Evidence |
|---|---|
| AC 16, HP 75, speed 120 ft | The "Wario's Motorcycle (Customized)" item record on Wario's own sheet (`tools/item sheet examples/wario.json`) — the customized getaway bike with the rear compartment and saddlebags the Scorncrow record shows. |
| CR blank | Vehicles have no challenge rating. |
| Abilities neutral 10s | A vehicle has no ability scores of its own; dnd5e requires the six fields anyway. The Ramming Speed attack rolls flat and says to use the driver's Strength + proficiency. |
| AC `calc: "flat"` | The 16 comes from armor plating / reinforced frame, matching Wario's own actor (`calc: "flat"`, not `"natural"`). |
| No difficult-terrain immunity | The chopper record claims it; the customized record does not, and the Scorncrow record proves the opposite — the motorbike stalled in the leaves and branches. |
| Token art `npc/ai/wario-bike.webp` | Already present in the campaign's Foundry data manifest, referenced by the same Foundry-relative convention as the other exports. |

**Other records of the same machine are not merged in.** Wario's sheet also
carries a weaponized "Custom Chopper" configuration (AC 16 / 75 HP / 70 ft,
flamethrower, spiked wheel guards, oil slick) and a summoned-mount block from
Wario Bike Summon (AC 14 / 50 HP / 60 ft). Both are documented inside the
actor and in `tools/build-wario-motorbike.py` rather than combined, because
no single record combines them.

## Peach's Castle, 955 BF — the court and Bowser's incursion

[`peachs-castle-955/`](peachs-castle-955/README.md) holds thirty era NPC
exports generated by `tools/build-peachs-castle-955-actors.py`: Princess Peach
alive, Toadsworth the Elder, the Captain of the Palace Guard, nine guard kits,
the household, the hooded Mages' Guild adept, and the "Interloper at the

touches them. Tokens are the cutouts under `portraits/peachs-castle-955/`.

```bash
python3 ../../tools/build-peachs-castle-955-actors.py            # write
python3 ../../tools/build-peachs-castle-955-actors.py --check    # verify
```

Every file carries a stable `_id` and a folder path (`Peach's Castle 955 BF /
The Court` or `/ Bowser's Incursion`), and
[`peachs-castle-955/import.json`](peachs-castle-955/import.json) is the
combined packet for the mass-import module — one Import, thirty actors in two
folders, re-importable without duplicates.

The 955 Bowser is a scene NPC. The present-day Bowser is still the player
character above — never import one over the other.
