# Peach's Castle, 955 BF — Foundry VTT actors

Thirty dnd5e NPC exports (system 5.3.3, core 14) for a session set inside
Peach's Castle on the night of `highsun_1_955_bf_the_day_of`, plus the
**"Interloper at the Council"** scene kit: Bowser and the force he brings when
he crashes a crucial palace meeting. One file per figure in the
[3D reference packet](../../../docs/3d-reference/peachs-castle-955/README.md);
every portrait and token is that figure's cutout.

All thirty are generated by
[`tools/build-peachs-castle-955-actors.py`](../../../tools/build-peachs-castle-955-actors.py)
— **do not hand-edit**; change the generator and re-run it (`check-all` runs its
`--check`). The sanitizer reports every file clean.

## Install

1. Copy `Reputation-Matrix2/portraits/peachs-castle-955/` to
   `<Foundry Data>/portraits/peachs-castle-955/` (tokens are 512-px PNGs with
   transparency). Paths in the JSON are `portraits/peachs-castle-955/<file>.png`.
   Or let the bridge do it:
   `python3 tools/foundry-bridge.py install-images Reputation-Matrix2/actors/peachs-castle-955 --foundry-data "<Foundry Data>"`.
2. **One click:** with the
   [Waluipedia Mass Import module](../../Foundry/mass_import/README.md) enabled,
   Actors sidebar → **Import** → URL
   `https://raw.githubusercontent.com/mikegent01/bik/gh-pages/Reputation-Matrix2/actors/peachs-castle-955/import.json`
   (or upload [`import.json`](import.json), or paste
   [`macros/import-peachs-castle-955.js`](../../Foundry/mass_import/macros/import-peachs-castle-955.js)
   into a script macro). It creates the folders *Peach's Castle 955 BF / The
   Court* and */ Bowser's Incursion*, all thirty actors with their fixed `_id`s,
   and reports any token the server cannot find. Running it again after a
   rebuild **updates** the thirty in place instead of duplicating them.
   Without the module: import each `fvtt-Actor-pc955-*.json` through the
   Actors sidebar (right-click → Import Data) or Plutonium.
3. Prototype tokens are unlinked, so dropping the same guard six times gives six
   independent HP pools. The court is disposition *friendly*, the incursion
   *hostile*.

`import.json` is generated —
`python3 tools/foundry-bridge.py combine Reputation-Matrix2/actors/peachs-castle-955 --out Reputation-Matrix2/actors/peachs-castle-955/import.json --world peachs-castle-955`
— and `check-all` fails when it drifts from the thirty files. Each actor's
folder lives in `flags["waluipedia-mass-import"].folderPath`; the `_id`s are
derived from the slug, so they never change between rebuilds.

A table-ready encounter for a 4–5 PC party of level 4–6: Bowser + 2 Koopatrol
at the main doors, a Sledge Bro and 4 Koopa Troopa Soldiers behind them, 2
Paratroopas through the windows, 1 Boo already inside, a Lakitu under the
vaulting, a Bob-omb Sapper on the side door. The court fights back with whatever
the players rally — the guard kits are built to be dropped in by the handful.

## Design notes

* Weapons carry real dnd5e attack activities (`dnd5eactivity000`), so they roll
  on import; the ability modifier is added by the system. Features are text
  (monster-type feats), with `uses` set for X/day and recharge abilities.
* No species, class, subclass or background items on any NPC; no invented
  magic items — the Captain's sealed order and the page's scroll are props
  with their contents left to the GM.
* Levels follow `data/abilityPoints.json` (Peach 4, Toadsworth the Elder 4,
  Bowser 8 present-day PC); the sheets never contradict the ledger.
* Alignments are table shorthand, not canon; the Koopa Troop regulars are
  *Lawful Neutral* because the present-day Troop is a protagonist faction.
* Item icons are Foundry core `icons/…` paths, verified against the DM's
  `image paths.txt` by the generator; the original art rule applies (no
  official Nintendo assets anywhere in the pipeline).
