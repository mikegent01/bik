## Commit 1 — Mass Import 1.1 (`6d6e252`)

`Reputation-Matrix2/Foundry/mass_import/` → **1.1.0**. The module now reads and writes the world's own **Data folder**: *Import from the Data folder* takes a file **or a directory** (`npc/waluipedia/cast`), walks subfolders, and either mirrors the directory tree as Foundry folders (`dirs`) or follows the `folderPath` flag (`flags`); non-actor JSON is listed as *ignored*, not imported. *Export to the Data folder* writes one file per actor under `npc/waluipedia/<world>/<folder…>/` plus a combined `import.json`, so the repo's bridge (`tools/foundry-bridge.py`, which already walks subdirectories) and Foundry see the same tree. Every import opens a **review table** first — include, rename, re-folder, new/update per row — before anything is created. The README's first section now says where the import-all files are (`KNOWN_PACKETS`: cast 152, Peach's Castle 955 BF 30, the midlands tree as a directory source) and the two new macros (`import-from-data-folder.js`, `export-to-data-folder.js`) ship in the zip. `tools/tests/test-mass-import-module.mjs` grew a fake Data folder (FilePicker browse / createDirectory / upload + fetch) and now runs 87 checks (91 with `WMI_EXPORT=`).

## Commit 2 — The 34 hand-authored sheets are player characters

**What changed.** `tools/build-character-sheets.py` builds every `BESPOKE` sheet as a dnd5e `type:"character"` actor instead of an NPC stat block. The templated 118 are untouched.

* **`PC_BUILD`** — one line per bespoke character: class, subclass, hit die, spell progression and ability, species item name, background item name. The builder refuses a bespoke entry without a `PC_BUILD` line.
* **Level = the XP ledger level** (`pc_level()`), the standing rule. Where the ledger has no row (Director Mario, Evil Mario, Fawthful, Mimbus, Paulo, Sans) the authored CR stands in, rounded up, never below 1. The authored CR is kept in `flags["waluipedia-sheets"].pc.cr` and the old rule — never above the ledger — still holds for it.
* **`pc_doc()`** mirrors the live PC exports (Bowser's intake sheet was the reference): class / subclass / species / background items with `details.race` / `background` / `originalClass` pointing at them, `hp.max` set numerically from the hit die and Constitution (`pc_hit_points()`), proficiency and save DCs from the level, XP at the level threshold, weapon and armour proficiencies by class, a **linked** prototype token, the `character` schema blocks (`currency`, `tools`, `spells`, `bonuses`, `resources`, `favorites`, `bastion`, `inspiration`, `weaponProf`, `armorProf`). A subclass appears from level 3 (the 2024 rule).
* **The authored kit stays.** Weapons are marked proficient, features become class features, *Multiattack* becomes *Extra Attack* — flagged *arrives early* when the sheet is under level 5 so the GM can hold it. Evidence quotes are unchanged; no spells are invented (a caster's class item carries progression and ability so Foundry computes the slots; the player picks the spells).
* **Validation** — `validate()` and `tools/check-sheets.py` now carry both rule sets: templated → `npc`, unlinked token, no class items; bespoke → `character`, linked token, exactly one class / species / background, class level == ledger level, subclass only from level 3, index `level` == actor level. The checker also fails if an actor's `bespoke` flag disagrees with the builder's tables.
* **Site** — the sheet page already had a PC renderer; the provenance lines on the article panel and the sheet page now read *Hand-authored as a player-character sheet — level 5 Monk, the ledger level (authored CR 5, never above it); a player may take this seat.* The index entry gains `level`, `classes`, `species`, `pc{…}`.
